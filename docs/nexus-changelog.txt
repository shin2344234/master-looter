For Crimson Desert 2.01.00 (exe 1.0.0.2760).

## Crashes

Fast travelling could kill the game. lsimo reported it and read the crash dump
before I did: a call through a null function pointer with this plugin on the
stack, twenty-four minutes into an ordinary session.

The mod queues work to run on the game's own thread, and it holds pointers to
the objects that work is aimed at. A teleport frees those objects. The queue did
not know that, so four seconds after the jump it drove a state change at a
gimmick that no longer existed. Anything queued when the world changes is now
thrown away, and the log says how many went.

A well run turned out to be a fourth place holding the same kind of pointer, and
the first fix only covered three. Winding a well is eleven seconds of timed
steps spread over many scans, so fast travelling part way through left it
driving freed objects on its own schedule. A run is abandoned when the world
changes under it.

The second crash nobody had reported. Installing a hook wrote the redirect into
the game's function before saving the address of the original, and every
redirect calls that original immediately. A game thread arriving in that gap
called through nothing at all. The window is a few instructions wide, but hooks
go in while the world loads and the function in question runs thousands of times
a second, so it was small and pointed at something fast. This would have looked
like the game dying at startup for no reason, with nothing useful in the log.

## Looting nothing at all

Cmz4455 reported no auto looting as Damiane or Oongka. Their log has the scan
walking away from the player and settling on a steam engine, after which every
part of the train counted as the player's own gear and was skipped, so nothing
in reach was picked up.

The mod scores what to centre on, and a dressed character should beat a vehicle
easily. It lost because the train brought enough separate parents into range to
push the player out of a table that only holds thirty-two, and once the player
is not in the table none of the protections against exactly this apply. The
thing being scanned around can no longer be pushed out of its own table, and
something whose children have never once been identified as items cannot take
the centre from something whose have.

## New

A Creatures tab, asked for by LuxDragon after ground lizards became catchable.
Search a species by name and set it to always or never. It beats the Insects,
Fish and Small animals switches, the same way a per-item override beats its
class. Ten catchable insects have no item behind them in the game's data, so
naming them was the only way to refuse them at all.

A key and a pad chord for taking owned goods, asked for by Ahplla. Unbound until
you set it, under General, Keys. Leaving that switch on earns a bounty, so it
wants turning on for a moment and off again, which a menu is a poor shape for.

## Smaller

Drawing a well no longer lets a vein you mined by hand collect the extra ore
from the tool bonus setting. Every well step was marking the vein bonus window
open, which is the one thing that setting promises cannot happen.

A settings file written before version 2 was migrated on every launch instead of
once, because the migration was never saved. That reverted a hand-edited
GatherUnknown on every start and left a spare backup each time, which pushed
real backups out of the twelve the Restore list keeps.

Loading a preset or restoring a backup now changes the menu language along with
everything else, instead of changing the setting and leaving the menu as it was.

The log names the mod that hooked DirectX before this one, rather than only
saying that something did. Faults in the log say "first chance" and carry a line
explaining that most of them are the game probing memory on purpose, because
they get pasted into reports as the crash and usually are not it. When a fault
does switch off ore breaking for a session, that now says so on screen instead
of the mod quietly getting worse.

The memory cache the scan leans on stopped working about five seconds into every
session, because a stale entry was left in front of the fresh one. It caches
again.
