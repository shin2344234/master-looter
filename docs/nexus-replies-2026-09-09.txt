=== to dofo7777 (Crimson Route author) ===

Appreciated, and easier if I just tell you exactly what this mod does to the
swapchain so you can see where it could collide.

It patches one vtable slot on the DXGI factory, CreateSwapChainForHwnd,
replacing the slot rather than detouring the function, so anything already there
still runs. When the game creates a swapchain it hands back a proxy object
implementing IDXGISwapChain4 that owns the real one and forwards everything,
including the waitable methods.

It deliberately does not hook Present, ResizeBuffers or SetColorSpace1 when it
finds those already detoured. It checks the first bytes for a jump and leaves
them alone if there is one, so two detours never end up stacked.

Since 1.6.2 it releases its back buffer references before a chain is destroyed,
which was its own crash on frame generation toggles.

The shape I would suspect is two proxies over one chain, where one of us hands
the other an object it does not expect to be handed. So the useful question is
whether Crimson Route also wraps or replaces the swapchain, or works through
Present alone, and what changes between your Present and DirectComposition
modes. ardenness found that with this mod removed, DirectComposition still
crashed for them and Present did not, which suggests the interaction is not
purely mine.

Happy to make a build with anything switched off if it would isolate something
for you.

=== to Cedricdur ===

The .asi disappearing from bin64 is almost certainly your antivirus taking it,
not the game or the mod manager. It is an unsigned DLL that gets injected into a
game and rewrites instructions in memory. A trainer does the same things, so a
model trained on trainers answers trainer. Four of seventy flag it, all of them
guesses, and none matching a known family.

Restore it from quarantine and exclude the game's bin64 folder, or build it
yourself from the GitHub source if you would rather not trust mine.

That also explains Insert doing nothing: no plugin, no menu. Once the file
survives a session it should behave.

=== to lsimo (bug report: game crashed after teleporting) ===

Still open, and I have already been wrong about it once, so here is where it
actually stands.

Pulling the dump apart yourself was the useful part. The return address landing
in MasterLooter.asi and RAX being zero told me where to look, and your log said
the rest. It faulted inside the game's own gimmick driver, the guard around that
call caught it and switched driving off, and a moment later something called
through a null pointer and took the process.

What I thought was happening: the mod queues work for the game's thread, each
job holding a pointer to the thing it aims at, and a teleport frees those
things. So 1.6.4 throws away anything queued when the world changes, and counts
what it threw.

That count has read zero every time, over many jumps, including ones with ore
actively being mined. The queue drains off a function that runs thousands of
times a second, so nothing sits in it longer than about a millisecond. There was
never a queue to purge, and my fix cannot be the fix. It stays in because it
costs nothing, but I have stopped claiming it.

So 1.6.4 does something more useful instead. Before the mod drives one of the
game's state machines, it now records what that object looked like an instant
earlier: its address, whether it was still readable, and the class it names
through its vtable. A live object names itself. A freed one has had its memory
reused and cannot. If this happens to you again, one line will say which, and
that ends the guessing.

No need to go hunting for it. It happened once in twenty-four minutes and not
since, so please just carry on and send the log if it ever comes back.

One thing you may have noticed after that crash: ore veins stopped breaking for
the rest of the session. That is deliberate, one fault and driving is switched
off rather than risking it again, but it used to happen silently. In 1.6.4 it
says so on screen and the log explains what still works and that a restart
brings it back.

Your hunch about the animation trimmer is reasonable. An instant teleport
narrows any window between the world going away and the mod noticing, and it
would explain why this is rare enough that I cannot reproduce it here.
