Test plan for 1.6.4

Only what is new and still unproven. No regression sweep: nothing in this
release touches ordinary pickup, gathering or mining, and you would notice
before I would. The one exception is at the bottom, because there is a specific
line of code behind it.

Already confirmed, nothing to do:

  Creature naming and item overrides. Six Ricefish and two Tench refused by
  rule, species named individually.
  The detour lines. They resolve to gameoverlayrenderer64.dll, so what hooks
  DirectX on your machine is the Steam overlay, not a mod.
  Well pace, back to once a second.
  Faults. None occurred, so there was nothing for the wording change to label.


1. Mount and dismount, a few times, while looting is running.
   The only test that has never produced a result. Do it near things actively
   being looted, then search the log for "dropped":

       [scan] paused: player actor changed (mount, cutscene or area); dropped N queued actions aimed at the old world

   The count used to be sampled once every five seconds while the thing it
   counted happened on the first scan of a hold, so it always read zero. It
   accumulates now. A number above zero is lsimo's crash not happening.

   Still zero after several tries means nothing is ever queued at a world
   change, which would tell me his crash came from somewhere I have not looked.

2. The owned goods key.
   General, Keys, "Take goods that belong to someone". Unbound. Press Rebind,
   then press a key. Find something the log is refusing with "owned by someone
   (theft)" and press it:

       Master Looter: taking owned goods, the game calls this stealing

   The item should then be taken, and pressing again should say it is leaving
   them alone. Quit and check KeyOwned in [MasterLooter] holds a number, since
   it currently reads 0.

3. The settings migration. Two restarts, one edit.
   Copy MasterLooter.ini somewhere safe. Delete the line reading
   ConfigVersion=2. Start, quit. The ini should say ConfigVersion=2 again and
   the log should say it migrated. Start and quit once more: it must not migrate
   twice, and MasterLooter.backups must not gain a second file ending -v1.


THE ONE REGRESSION WORTH CHECKING

Naming creatures from status+0x30 runs on every creature, not only the ones you
filter, so it is the one change that could quietly do the wrong thing. If a
species resolved wrongly, the wrong item rule would apply and something would be
refused that should not be.

Leave Item_Ricefish set to never and go back to the water. Ricefish should be
left alone and everything else should still be caught. If other fish stop being
caught too, the row is over-matching and I want the log.

That is the whole check. One observation, and it separates "naming works" from
"naming matches too much".


NOT WORTH YOUR TIME

The ore bonus during a well. Real fix, one line moved, but testing it means
hand-swinging a vein inside the two seconds a well is winding. Skip unless vein
counts start looking wrong.

The hook installer race, the train from #36, and the memory cache. None can be
triggered on purpose, and I said so before.
